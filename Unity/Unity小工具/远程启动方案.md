普通台式电脑的远程启动，核心仍然是 **Wake-on-LAN（WOL）**。与笔记本相比，台式机的优势在于通常配备**有线网卡**，且 ATX 电源在关机后持续为网卡提供 +5V 待机供电，硬件条件更成熟；需要额外关注的是主板 BIOS 中的节能选项（ErP、Deep Sleep）以及外网唤醒时的路由器配置。

------

## 一、硬件前提检查

在开始任何设置之前，建议先确认以下两点：

- **有线网卡**：WOL 依赖有线网卡，Wi-Fi 唤醒（WoWLAN）兼容性极差，普通台式机不建议考虑。
- **电源标准**：电源需符合 **ATX 2.01** 或以上标准，关机后能为网卡持续提供待机供电。

一个非常实用的快速判断方法：**关机后观察网口指示灯**。如果灯还亮着或会闪烁，说明网卡在关机状态下仍有供电，配置成功的概率很高；如果灯完全熄灭，问题一定在 BIOS 的节能设置层面，此时改 Windows 设置是无效的。

## 二、BIOS 设置（最关键的一步）

开机时反复按 `Del`（或 `F2`）进入 BIOS，切换到 **Advanced Mode**（高级模式）。不同品牌主板的选项名称略有差异，但需要处理的核心项是一致的：

### 必须开启的选项

| 选项名称（常见叫法）                                         | 设置                |
| :----------------------------------------------------------- | :------------------ |
| **Wake on LAN** / Resume by LAN / Power On By PCI-E / PCIE/Networking 设备唤醒 | **Enabled（启用）** |

华硕主板通常在 `Advanced → APM Configuration → Power On By PCI-E` 中设置；微星主板在 `SETTINGS → 高级 → 唤醒事件设置 → PCIE/Networking设备唤醒` 中改为“允许”。

### 必须关闭的节能选项

| 选项名称                               | 设置                 | 原因                                                         |
| :------------------------------------- | :------------------- | :----------------------------------------------------------- |
| **ErP Ready** / ErP Support / EuP 2013 | **Disabled（关闭）** | 启用后会切断关机状态下网卡的待机供电，WOL 在物理层面无法成立 |
| **Deep Sleep Control**                 | **Disabled（关闭）** | 部分 Dell 等品牌机默认开启，效果同 ErP，会切断网卡供电       |
| **PCIe ASPM**（如有）                  | **Disabled**         | 低功耗链路状态可能干扰网卡在待机时侦听 Magic Packet          |

设置完成后按 `F10` 保存并退出。

## 三、Windows 系统配置

进入系统后完成以下三处设置。

**1. 关闭“快速启动”**

快速启动本质是混合关机，关机后网卡所处的状态与真正的 S5 不同，这是“睡眠能唤醒、关机唤不醒”最常见的原因。

路径：控制面板 → 电源选项 → 选择电源按钮的功能 → 更改当前不可用的设置 → **取消勾选“启用快速启动”** → 保存修改。

**2. 网卡电源管理**

设备管理器 → 网络适配器 → 右键有线网卡 → 属性 → **电源管理** 选项卡：

- 勾选 **“允许此设备唤醒计算机”**
- 勾选 **“只允许幻数据包唤醒计算机”**
- **取消勾选“允许计算机关闭此设备以节省电源”**（这一项是“刚关机能唤醒、过几分钟失效”的头号嫌疑）

**3. 网卡高级选项**

仍在网卡属性中，切换到 **高级** 选项卡，确认以下项为 **Enabled**（启用）：

- **Wake on Magic Packet**
- **Shutdown Wake-On-LAN**
- **启用 PME**（部分网卡此选项名称不同，作用相同）

如果反复不灵，可以进一步关闭网卡的 **Energy Efficient Ethernet、Green Ethernet、ARP Offload、NS Offload** 等节能特性。

## 四、获取 MAC 地址并进行局域网测试

在目标台式机上打开命令提示符，执行：

cmd

```
ipconfig /all
```



找到有线网卡的 **物理地址**（格式如 `XX-XX-XX-XX-XX-XX`）。

先用一台**同一局域网内的设备**（另一台电脑或手机 App）向该 MAC 地址发送 Magic Packet，端口通常为 **9** 或 **7**，目标地址可填子网广播地址（如 `192.168.1.255`）。这一步的目的是排除外网因素，确认局域网内 WOL 本身是否工作。

如果局域网测试成功、关机后也能唤醒，再进入外网方案。

## 五、外网唤醒方案（从外网启动）

需要实现“人在外面，启动家里台式机”时，仅靠 WOL 本身不够，还需要路由器配合。有两种主流路径：

### 方案 A：路由器端口转发 + DDNS（直接）

1. **为台式机设置 DHCP 静态保留**：在路由器中把台式机的 IP 与 MAC 绑定，确保内网 IP 不变。
2. **端口转发**：将外网的一个端口（如 `UDP 9` 或自定义端口）转发到台式机的内网 IP 和 WOL 端口。WOL 通常使用 **UDP** 协议。
3. **DDNS（动态域名）** ：家庭宽带公网 IP 通常是动态的，在路由器上启用 DDNS 服务（如 TP-Link、华硕等品牌自带），用一个固定域名代替变化的 IP。
4. 在外网使用手机 WOL App，向“DDNS 域名 + 转发端口”发送 Magic Packet。

### 方案 B：VPN 回内网后发唤醒（更稳妥）

先通过 VPN 拨入家庭内网，再在内网环境中发送 Magic Packet。这种方式避免了将 WOL 端口直接暴露在公网，安全性更好，也是排查复杂网络环境时更推荐的做法。

## 六、常见失败原因速查

| 现象                           | 优先检查                                                     |
| :----------------------------- | :----------------------------------------------------------- |
| 关机后网口灯**不亮**           | BIOS 中 **ErP Ready** 或 **Deep Sleep** 未关闭；电源待机供电不足 |
| 睡眠能唤醒，**关机唤不醒**     | Windows **快速启动** 未关闭；网卡未勾选 **“只允许幻数据包唤醒计算机”** |
| 刚关机能唤醒，**过几分钟失效** | 网卡“允许计算机关闭此设备以节省电源”未取消；路由器 **ARP 表老化**，需做静态 IP-MAC 绑定 |
| 局域网能唤醒，**外网不行**     | 路由器端口转发未配置或协议选错（应为 **UDP**）；DDNS 未生效；公网 IP 是否为 NAT 环境 |
| 使用 USB 网卡或扩展坞网口      | 这类网卡通常不支持或不稳定支持 WOL，建议使用主板板载有线网口 |

> **最稳妥的兜底方案**：如果主板 ACPI 供电存在缺陷导致 WOL 始终不稳定，可以退而求其次，在 BIOS 中开启 **“来电自启”（AC Power Loss → Power On）** ，配合一个可远程控制的智能插座，通过断电再通电触发开机。这一方案不依赖网卡待机供电，适合老旧或特殊主板。

**配置顺序建议**：先完成 **BIOS（开 WOL、关 ErP/Deep Sleep）** → **Windows（关快速启动、网卡电源管理）** → **局域网测试验证** → 再处理**路由器外网转发**。每改完一步做一次完整关机测试，避免同时修改多项导致无法定位问题来源。
